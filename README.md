# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 巡检排班与隐患联动规则

纯前端没有后端时钟，业务"今天"固定为示例基准日 `BUSINESS_TODAY = 2026-10-06`（`src/data/patrol-domain.ts`），
避免随访问设备系统时钟漂移导致演示周错位。

- **排班视图**：巡检页「排班视图」横为一周（周一起）、竖为班组，格内是当天巡检路线与计划日期；
  点任意有任务的格子带班组+周过滤跳回「任务明细」。看板格内合计与明细按周条数取自同一份规范化结果，
  页内有"账实核对：条数一致"标识；运营概览（`/`）与看板共用 `patrolSummary()`，不允许出现两个数。
- **去重**：同一路线同一天重复排班只留一条，按**巡检编号**排序保留最靠前的一条，其余并入主记录
  「合并自」与操作轨迹；原始行物理保留（审计可追溯），明细/排班/概览只认去重后的规范化结果。
- **存量回填与班组推定**：计划日期缺失用完成时间回填；早年没有巡检班组的按路线归属推定——
  固定归属表（东段电缆舱→巡检一班、西段综合舱→巡检二班、南段燃气舱/北段给水舱→巡检三班），
  表外按路线名首关键字（东/西/南/北/中）落到分管班组，再无法判断兜底「综合巡检班」，保证班组不为空。
  推定记录在界面上打「推定」标记。
- **往期单据**：按抄表周期搬入的巡检标「抄表周期搬入」并记录周期；早期只有纸面的，按**扫描件编号**
  建账（数据来源=扫描件，如 `SCAN-2025-0117`）。
- **隐患同步**：「上报问题」把发现问题数写入巡检并转「已上报」，系统按项展开为隐患条目
  （编号 `HAZA-XJ-<巡检编号>-<序号>`）挂「待整改」，整改期限=计划日期+7 天；每条隐患对应一张派工单。
  隐患台账与派工清单逐条同源：处理意见在任一侧回写两边同步，状态动作两边联动。
- **幂等**：同一动作对同一记录连续触发多回，账上只落一次状态，后续并入同一条操作轨迹，不重复记隐患/派工。
- **重试**：本地存储写入（模拟超时/断线）失败允许重试一次，再失败把具体原因透传到页面提示。
- **关键条目**：`/focus` 罗列班组超载（一天 ≥3 条）、路线空窗（连续 >3 天无人）、重复排班去重、
  待整改隐患；运营概览里呈现同一版（近 14 天同日分布柱图 + 关键条目简版）。

### 老数据兼容与既有结论

读取时对存量数据做**增量规整**（幂等，可重复执行）：补齐新增字段、占位"样例"文本按无值处理、
发现问题数转非负整数、按终态重算派生的 `pending`（旧版该标志算错会由此修正）。
**不改写任何既有业务结论**：已有 `status`、`abnormal` 与人工处理意见保持原值，巡检同步的隐患采用
独立编号段，只新增、不覆盖。示例种子里的占位巡检/隐患数据为脚手架演示数据，本次替换为贴合业务的真实数据。
另修正了入廊作业审批一处既有的动作映射错位（「确认批准」误映射到"已驳回"、「驳回申请」误映射到"已完工"）。
